# ADR 0001: 固定保存活動開場實力分數

## Status

Accepted

## Context

產品需要在活動結束後顯示每位活動參賽者的開場分數、結束分數與整日差額。現有資料只保存球員目前的 Glicko-2 狀態，修改或刪除歷史後會全量重算，因此無法穩定回答「當天活動開始時看到的分數是多少」。

可考慮每次從目前歷史動態回推，但這會讓活動開場分數隨日後的歷史修正而改變，失去歷史快照的語意。既有活動則沒有可直接使用的快照。

## Decision

- 開始活動時，固定保存當時所有已建立球員的完整 Glicko 狀態（rating、RD、vol）；畫面只顯示 rating。
- 活動開場狀態同時是該活動內 rating 重算的固定邊界。更早活動的歷史修正不得穿透並改寫本活動或其後活動。
- 修改或刪除某活動內的比賽時，從該活動的固定開場狀態重播該活動比賽；影響止於下一個活動的開場邊界。
- 活動中才建立的球員，以建立時的完整初始 Glicko 狀態作為該活動的基準，並在摘要標示為「活動中新增」。
- 升級既有資料時，依遷移當下的有效歷史回放至各活動開始時間，補出一次完整開場狀態；補齊後即固定保存。
- 若某個既有活動無法為所有活動參賽者可靠回推開場分數，該活動不顯示活動摘要；原有比賽紀錄仍保留。

## Consequences

- 活動摘要能忠實呈現當時的開場基準，不會因日後修正更早活動的歷史而漂移。
- 每個活動的開場、逐場變動與結束分數可以保持數學一致。
- 需要擴充活動資料、保存完整 Glicko 開場狀態並維護舊資料遷移。
- 修正某活動的比賽不再像舊行為一樣影響所有未來活動；影響會在下一個活動開場邊界停止。這是為了保留各活動實際採用的起始狀態與可核對摘要。
- 活動結束分數與該活動內的單場分數變動仍會依該活動目前有效紀錄重算。
- 舊活動的回填值代表遷移當下可由有效歷史推得的最佳結果，而非過去已實際保存的原始快照；資料不完整時寧可省略整份活動摘要，也不顯示估算或部分結果。
